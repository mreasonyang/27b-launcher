# 网络共享确认弹窗修复

> 2026-09-30 状态说明：本文记录 0.10.7 的确认弹窗时序修复。后续 0.10.10 已通过 computer use 验证弹窗展示与取消，0.10.11 已恢复安装路径的窗口连接；“工具无法绑定”不再是当前阻塞。实际确认开放 LAN、密钥轮换和跨设备访问仍未人工实测，提交路径的证据仍来自自动回归。最新范围见[当前验收记录](../../docs/ACCEPTANCE.zh-CN.md)。下文保留当次证据。

版本：0.10.7 (36)

## 原因与修改

确认按钮启动异步任务，再从 `pendingBindMode` 读取用户选择。SwiftUI 关闭确认弹窗时会把 `isPresented` 写为 false，其 setter 清空了 `pendingBindMode`。任务开始后读取到 nil，直接返回，表现为点击确认没有反应。

使用 confirmationDialog 的 `presenting` 参数保存本次展示的数据，按钮把捕获的监听范围传给 `confirmBindMode(_:)`。异步流程不再依赖弹窗关闭时会被清空的临时状态。取消/关闭仍只清除待确认状态，不应用设置。实际切换继续复用既有重启、错误提示、忙碌状态和 API 密钥配置。

## 回归

新增测试覆盖运行/停止两种状态，以及弹窗关闭先于按钮回调、先于异步任务两种时序。旧实现四组均失败，修复后验证监听偏好持久化；运行状态恰好重启一次并更新实际监听范围；停止状态仅保存设置。另有取消测试确认没有修改偏好或启动/停止服务。

全量回归发现已有引导在“打开聊天失败 + 长模型 ID + 英文”时自然高度为 574 pt。错误提示现在替换原打开聊天说明，复制地址按钮与错误同行，避免重复占高。原有四语种一屏断言保留，并明确检查模型 ID 已加载。

代码自审：检查弹窗捕获值、取消路径、控制器权限/忙碌检查及重启错误传播。没有改动日常主界面布局或服务认证参数。
